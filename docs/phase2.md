# Phase 2: Web UI

## 何をしたか

FastAPI + バニラ JS の Web UI を追加した。

- `repdf/jobs.py`: `JobStore`/`Job` でアップロード〜生成の状態をメモリ上に保持。
  ジョブごとに一時ディレクトリ(`<base>/<job_id(UUID4)>/`)を持ち、アップロード直後に
  全ページを 100dpi の JPEG でプレビュー生成する
- `repdf/pipeline.py`: `sanitize()` に `progress_callback` を追加(既存呼び出しは
  引数省略で変更なく動く後方互換)。ページを1枚処理するたびに `(処理済み, 総数)` を通知する
- `repdf/app.py`: `POST /api/upload`・`GET /api/job/{id}/preview/{n}`・
  `POST /api/job/{id}/render`・`GET /api/job/{id}/status`・
  `GET /api/job/{id}/result.pdf`・`/result.md`・`/audit.json`。
  `job_id` は UUID4 のみを正規表現で受理し、パストラバーサル対策にしている
- `static/`: アップロード → サムネイル一覧・ページ削除(クリックまたは `3,5-7` 形式の
  レンジ入力) → 矩形描画(ドラッグで黒/白塗り領域を追加、複数可) → 生成 →
  ページ単位の進捗表示 → ダウンロード、という一連の画面
- `run.sh`: `uvicorn` 起動スクリプト。既定で `127.0.0.1` にのみバインドし、
  `REPDF_HOST` を明示指定すると警告を出す

## なぜしたか

CLI の `--boxes boxes.json` は座標を人間が手で書く必要があり非現実的だった。
矩形領域を視覚的にドラッグ指定できる UI が必要だったため。あわせて、複数ページの
PDF を扱う際にページ単位の削除・進捗確認ができた方が実用的と判断した。

## 検証

- `tests/test_app.py`: FastAPI `TestClient` で 20 件(アップロード成功/失敗、
  プレビュー取得、パストラバーサル対策、render の一連の流れ、
  `audit + textLayer≠extract` が 400 になること、markdown/audit の有無に応じた
  ダウンロード可否など)
- 実 PDF(8ページの日本語 LaTeX 文書)を使い、`run.sh` でサーバーを起動して
  `curl` で実際に一連の操作を確認した:
  - アップロード → 8ページ検出、プレビュー JPEG が正しい見た目であることを目視確認
  - ページ削除(1ページ) + 矩形黒塗り + `markdown: true` + `audit: true` を
    指定して render → ステータスをポーリングし、進捗(`current`/`total`)が
    リアルタイムに更新されることを確認
  - 生成結果をダウンロードし、PyMuPDF でページ数(7)・メタデータ空を確認、
    `pdftotext` で黒塗り指定した範囲のテキストが消えていること(指定した矩形の
    外側は意図通り残ること)を確認
  - Markdown・監査 JSON(8件)がダウンロードできることを確認

### ブラウザでの実操作確認とそこで見つかったバグ

当初この実行環境には Chromium 等のブラウザ自動操作手段がなく、バックエンド API の
確認(`curl`/`TestClient`)とフロントエンドコードの目視レビューのみで済ませていた。
その後 Playwright + Chromium をこの venv に導入し(`requirements-dev.txt`、
`playwright install chromium` で本体を別途取得)、実際にブラウザ操作で確認したところ、
2件のバグが見つかった:

1. **`hidden` 属性が効かず矩形編集モーダルが常に開いたまま、閉じるボタンも無反応**。
   原因は CSS の詳細度ではなくカスケードの `origin` の話で、UA スタイルシート由来の
   `[hidden]{display:none}` は、詳細度に関わらず author スタイルシートの通常ルール
   (`label{display:block}` など)に必ず負ける。`[hidden]{display:none !important;}`
   を明示的に追加して解消した
2. **矩形編集で黒塗り位置が意図した場所からずれる**(実際にユーザーが手元のブラウザで
   発見)。画像の高さがモーダルの表示領域より大きくスクロールが発生する場合、座標
   計算の基準にしていた `#box-editor-draw-layer` はスクロール前の表示領域サイズの
   まま固定されており、「表示領域内での相対位置」を「画像全体に対する比率」として
   誤って扱っていた。画像が必ずモーダル内に完全収まるよう CSS を直し、JS の座標計算も
   `draw-layer` ではなく `img` 要素の実際の表示矩形を基準にするよう修正した

いずれも Playwright で実際にドラッグ操作→生成→ダウンロード→`pdftotext` での内容確認
まで通しで検証し直し、解消を確認済み。
