# Phase 1: コアパイプライン・CLI

## 何をしたか

PDF を丸ごとラスタライズして再構成する中核処理と、それを叩く CLI を実装した。

- `repdf/models.py`: `TextItem`(テキスト+座標+信頼度)。OCR方式・可視テキスト抽出方式が
  最終的にここへ合流する共通データモデル
- `repdf/visibility.py`: PDF 内のテキストが人間の目に見えるかを判定するヒューリスティクス
  (レンダリングモード・不透明度・背景色一致・極小フォント・ページ範囲外)
- `repdf/providers.py`: テキストレイヤーの2方式
  - `extract(page)`: 元 PDF のテキストから可視な部分だけを抽出(visibility.py を使用)
  - `ocr(image, lang, dpi)`: tesseract の TSV 出力を解析して座標付きテキストを得る
- `repdf/layer.py`: 画像の上に `render_mode=3` の透明テキストを重ねて1ページ分の
  PDF を組み立てる。日本語は PyMuPDF 組み込みの CJK フォント(`japan`)で描画する
  (ASCII も同じフォントでカバーできることを実測で確認済み)
- `repdf/pipeline.py`: `sanitize()` が全体を統合する。ラスタライズ→矩形塗り→
  テキストレイヤー生成→メタデータ除去→保存
- `repdf/markdown.py`: サニタイズ後のテキストを Markdown サイドカーとしても出力できる
  (簡易版。行の再構成は Y 座標の近さで行をグルーピングするヒューリスティクス)
- `repdf/cli.py`: `python -m repdf.cli` として上記を呼び出す

## なぜしたか

PDF をそのまま AI に読ませると、目に見えない隠しテキスト(不可視レンダリングモード・
背景色と同化した文字・メタデータなど)が意図しない出力の原因になりうる。単にページを
削除するだけでは残ったページの隠しテキストは消えない。全ページを画像化してから
テキストレイヤーを作り直すことで、これらを物理的に除去しつつ検索性も確保する。

設計判断の詳細は `docs/investigation-visibility-api.md`(PyMuPDF の可視判定 API 調査)
と、承認済みの実装計画を参照。

## 実装中に見つかった設計上の問題と対応

- **build_page のページサイズ計算バグ**: 当初、新規ページのサイズを画像のピクセル数
  そのまま pt として使っていたため、高 dpi でラスタライズすると実物よりはるかに
  巨大なページになってしまっていた(A4 を 200dpi でラスタライズすると 23×32 インチ相当)。
  ページサイズは元 PDF の `page.rect`(pt 単位)を使うよう修正した。
- **黒塗り領域のテキストが抽出方式で残ってしまう問題**: `text_layer="extract"` は
  元 PDF のテキストオブジェクトから直接読むため、画像側を黒塗りしてもテキスト
  レイヤーには元のテキストがそのまま残ってしまっていた(OCR方式は画像からしか
  読まないため元々問題なし)。`pipeline.py` の `_drop_items_in_boxes()` で、黒塗り
  領域と重なる `TextItem` を明示的に除外するようにした。

## 検証

`tests/test_sanitization_guarantees.py` で、可視テキスト・不可視テキスト3種
(レンダリングモード3・白背景白文字・ページ範囲外)・メタデータを詰め込んだ PDF を
実際に `sanitize()` に通し、`pdftotext`(外部ツール)と PyMuPDF の両方で:

- 不可視テキストが一切残っていないこと
- 可視テキストは残っていること
- メタデータが空であること
- 黒塗り指定した領域のテキストが残っていないこと

を確認している。OCR 方式のテストは tesseract がインストールされている環境でのみ実行される
(未導入ならスキップ)。

## 既知の問題・TODO

- **可視判定はヒューリスティクス**: `visibility.py` の判定条件に当てはまらない
  隠し方(例: 極端に薄いが白ではない色、特殊なブレンドモード等)には対応できていない。
  保証を最優先するなら `text_layer="ocr"` を使う方が安全(画像に描画されないものは
  原理的に読み取れないため)
- **OCR の日本語精度は未検証**: この開発環境に `tesseract-ocr-jpn` が入っていないため、
  実際の日本語 PDF での精度確認ができていない。Phase 3 で低信頼度語のレビュー機能を
  追加する前提
- **Markdown サイドカーの行組み立ては簡易的**: Y 座標の近さだけで行をグルーピングして
  いるため、段組みレイアウトなどでは行の順序が崩れる可能性がある
- **透明テキストの配置はベストエフォート**: bbox の高さからフォントサイズを逆算し、
  bbox 下端をベースラインとして配置する近似。文字送りの正確な再現はしていない
  (検索・コピペの用途では実用上問題にならない想定)
- CLI では黒塗り矩形の指定に JSON ファイルが必要(座標を手で書くのは非現実的)。
  Phase 2 の Web UI で視覚的に指定できるようにする

## 使い方

```sh
python -m repdf.cli input.pdf -o output.pdf \
    --remove 3,5-7 \
    --dpi 200 \
    --text-layer extract \
    --boxes boxes.json \
    --fill black \
    --markdown output.md
```

`boxes.json` の例(1-indexed ページ番号 → 正規化座標 0.0-1.0 の矩形リスト):

```json
{
  "2": [[0.1, 0.1, 0.5, 0.2]]
}
```
