# extract/OCR差分による監査レポート機能

## 何をしたか

`repdf/audit.py` を追加し、`sanitize()` に `audit_path` 引数(CLIでは `--audit`)を
追加した。`text_layer="extract"` で採用されたテキストのうち、同じ位置を OCR しても
検出されないものを「疑わしい」として JSON に書き出す。自動除去はしない。

## なぜしたか

`visibility.py` の可視判定はヒューリスティクスの積み重ね(レンダリングモード・
不透明度・背景色一致・極小フォント・ページ範囲外)であり、これに当てはまらない
隠し方は見逃す。例えば「通常のテキストの上に、後から同色の図形を重ねて視覚的に
隠す」場合、テキスト自体の render_mode・color・size はすべて正常なので
`visibility.py` では検出できない。

OCR は実際に画像へ描画されたものしか読み取れないため、「元PDFのテキストとしては
存在するが、OCR では検出されない」という不一致は、可視判定の見落としを示す
強いシグナルになる。ユーザーからの提案を受けて実装した。

抽出方式(`extract`)自体をやめて OCR 方式に統一する選択肢もあったが、OCR は
日本語の複雑な字形で読み落とし(偽陰性)が起きうるため、正当な可視テキストまで
自動的に消してしまうリスクがある。そのため「抽出方式の速度・精度は維持しつつ、
不一致は警告として人間の確認に委ねる」設計にした。

## 実装

- `repdf/audit.py`: `find_suspicious_items(extract_items, ocr_items)` が、
  extract 側の各 `TextItem` について、OCR 側のどの `TextItem` とも bbox が
  重ならないものを `SuspiciousItem` として返す。単語単位(OCR)と行単位(extract)で
  粒度が異なるため、判定は「一部でも重なっていれば対応するとみなす」緩めの基準
- `pipeline.py`: `audit_path` が指定されると、抽出方式の処理と同時に該当ページを
  OCR し、差分をページ番号(1-indexed)付きで JSON に集約する。
  `text_layer != "extract"` での指定はエラーにする(意味を持たないため)

## 検証

`tests/test_pipeline.py::TestAuditReport` で、意図的に「テキストとしては通常だが、
後から白い矩形で覆い隠したテキスト」を含む PDF を作り、実際に検出できることを
確認している(`visibility.py` 単体では検出できないケースであることがポイント)。
あわせて、audit は警告のみで出力 PDF からの自動除去はしないことも確認済み。

実 PDF(8ページの日本語 LaTeX 文書、隠しテキストなしと確認済み)で試したところ、
当初は 24 件の誤検知が出た。中身を見るとすべて 1〜2 文字の短い断片(記号・数字・
単一アルファベット)で、コードリストの行番号など OCR が読み落としやすい箇所に
集中していた。`_MIN_TEXT_LENGTH = 2` で1文字のテキストを判定対象から除外したところ
2件まで減少し、残りもコードリストの行番号(`fgetstest.c` の行番号 `11`, `14`)という
説明のつく偽陽性だった。

## 既知の問題・TODO

- **OCR の読み落としによる偽陽性がありうる**: 短いテキストは `_MIN_TEXT_LENGTH` で
  除外しているが、2文字以上でも小さいフォントや特殊字形では読み落としが起きうる。
  最終判断は人間に委ねる設計はこのため
- **処理コストが増える**: `--audit` を使うと該当ページを textract 方式に加えて
  OCR でも処理するため、その分遅くなる
- **座標の重なり判定は粗い**: IoU等の厳密な指標ではなく、単純な矩形重なりの
  有無のみで判定している。閾値付きの精緻化は今のところ行っていない
